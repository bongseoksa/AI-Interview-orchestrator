# 06 — GUI 보완계획: DeskRPG 레퍼런스 갭 분석 + 단계별 개선

> 작성일: 2026-07-31
> 근거: DeskRPG 실제 화면(스크린샷) vs 현재 MVP 비교

## 1. 현재 MVP vs DeskRPG 갭 분석

### 1-1. 레이아웃 구조

| 영역 | DeskRPG | 현재 MVP | 갭 |
|------|---------|----------|-----|
| **메인 캔버스** | 탑다운 2D 사무실 — MEETING, LOUNGE, RESTROOM, ENTRANCE 등 공간 구분, 가구/나무/의자 배치 | CSS grid 카드 나열 (4열) | **공간감 없음** — 카드가 아닌 "방"이 필요 |
| **우측 패널** | "오피스 메신저" — 에이전트별 이름+색상, 대화체 말풍선, 이모지, 성격 드러남 | Activity Feed — `type` 태그 + 단조 메시지 | **대화감 없음** — 로그가 아닌 "대화"여야 |
| **하단 패널** | "직원 대시보드" — 에이전트별 스탯 바(스트레스/행복도/생산성), 성격 태그, 접기 토글 | 없음 | **에이전트 상태 대시보드 미존재** |
| **상단 바** | 오피스 예산, 가이드, 설정, 공유, 일차(D+N), 시간대(오전/오후) | 타이머, 토큰, 연결상태 | 비교적 양호, 보강 가능 |

### 1-2. 캐릭터 표현

| 요소 | DeskRPG | 현재 MVP | 갭 |
|------|---------|----------|-----|
| **아바타** | 픽셀 아트 스프라이트, 색상·헤어·체형 개성 구분 | 이모지 아이콘 (💤⌨️🔧 등) | **캐릭터 부재** |
| **이름표** | 캐릭터 위 이름 라벨 (강철두, 조이 등) | 카드 제목에 role 텍스트 | 양호하나 공간 내 배치 아님 |
| **이동** | 캐릭터가 사무실 내 걸어다님 (책상→회의실→라운지) | 정적 카드, 이동 없음 | **이동 애니메이션 없음** |
| **상호작용** | 캐릭터 클릭 시 대화, 도구 사용 시 해당 오브젝트로 이동 | 없음 | **인터랙션 없음** |

### 1-3. 커뮤니케이션

| 요소 | DeskRPG | 현재 MVP | 갭 |
|------|---------|----------|-----|
| **대화 스타일** | 자연어 대화체, 괄호 속마음, 이모지, 에이전트 성격 반영 | 구조화 로그 (`agent.started`, `tool.finished`) | **사무적 로그 vs 생동감 있는 대화** |
| **에이전트 색상** | 에이전트별 고유 색상 (레오=초록, 강철두=파랑 등) | 카테고리별 색상 (crew=초록, agent=파랑) | 에이전트별 색상 미적용 |
| **말풍선 구분** | 공개 발화 vs (괄호) 속마음 구분 | 구분 없음 | 발화/사고 구분 가능(LLM thinking vs agent output) |

### 1-4. 대시보드/통계

| 요소 | DeskRPG | 현재 MVP | 갭 |
|------|---------|----------|-----|
| **에이전트별 스탯** | 스트레스/행복도/생산성/연애운 프로그레스 바 | 없음 | 우리 맥락에 맞는 스탯 필요 |
| **성격 태그** | 워커홀릭, 포멀, 사교가, 스포티 등 뱃지 | 없음 | backstory에서 추출 가능 |
| **직원 관리** | 접기/펼치기, 직원 관리 버튼 | 없음 | |
| **전체 지표** | 평균 스트레스: 25.2% | 총 토큰만 표시 | |

## 2. 보완 단계 (우선순위순)

### Phase A — 메신저 패널 전환 (Activity Feed → Office Messenger)

**목표**: 로그 피드를 DeskRPG식 "오피스 메신저"로 전환. 가장 적은 작업으로 가장 큰 체감 변화.

변경 범위: `index.html` 우측 패널만 수정 (백엔드 무변경)

- [ ] 피드 제목: "Activity Feed" → "오피스 메신저"
- [ ] 에이전트별 고유 색상 할당 (role 해시 → HSL)
- [ ] `agent.completed` 이벤트를 **말풍선 형태**로 렌더링 (에이전트 이름 + 발화 텍스트)
- [ ] `llm.completed`를 **(괄호 속마음)** 스타일로 표시 — 사고 과정
- [ ] `tool.*` 이벤트를 작은 시스템 메시지로 표시 ("`{agent}` 님이 `{tool}`을 사용합니다")
- [ ] crew 시작/종료를 구분선 + 배너로 표시
- [ ] 하단 "최신으로" 버튼 (auto-scroll 토글)
- [ ] 폰트 크기 조절 (A- / A+)

### Phase B — 에이전트 대시보드 (하단 패널 신설)

**목표**: DeskRPG의 "직원 대시보드"를 우리 컨텍스트에 맞게 적용.

- [ ] 하단에 접기/펼치기 가능한 대시보드 패널 추가
- [ ] 에이전트별 카드:
  - 상태 인디케이터 (dot: 초록=활성, 회색=유휴, 빨강=오류)
  - 성격 태그 (backstory에서 키워드 추출: "전략 컨설턴트", "Devil's Advocate" 등)
  - **진행률**: 현재 태스크 진행 상태 (시작됨/완료 비율)
  - **토큰 사용량**: 에이전트별 누적 토큰 프로그레스 바
  - **태스크 완료**: 완료 태스크 수 / 전체 태스크 수
  - **마지막 발화**: 최근 출력 요약 (1줄)
- [ ] 전체 요약: "활성 에이전트: 2/13 | 평균 토큰: 4.2k | 완료 태스크: 3/5"

### Phase C — 공간형 레이아웃 (카드 그리드 → 사무실 평면도)

**목표**: 카드 나열을 DeskRPG식 탑다운 사무실 공간으로 전환.

이것이 가장 큰 변화이며, 두 가지 경로가 있다:

#### C-1. CSS/DOM 방식 (권장 — 빠르고 접근성 유지)

- [ ] `#desks` 그리드를 **CSS position absolute 기반 평면도**로 교체
- [ ] 영역 구분: 업무 공간(Work Room), 회의실(Meeting), 휴게 공간(Lounge)
- [ ] 각 에이전트를 원형 아바타 + 이름표로 표현 (이니셜 or 아이콘)
- [ ] 상태에 따라 위치 이동: idle → Lounge, working → 자기 책상, crew active → Meeting Room
- [ ] CSS transition으로 이동 애니메이션 (transform + 0.5s ease)
- [ ] 배경에 반투명 영역 표시 (책상=사각형, 회의 테이블=원형)

#### C-2. Canvas 2D 방식 (고도화 — agent-town식)

- [ ] HTML5 Canvas에 절차적 렌더링 (스프라이트시트 불필요)
- [ ] 간단한 도형으로 캐릭터 표현 (원+삼각=머리+몸, 에이전트 색상)
- [ ] A* 또는 직선 경로탐색으로 이동
- [ ] 오브젝트 배치: 책상, 화이트보드, 서류 캐비닛, 노션 문서함, 검색 단말
- [ ] HTML 오버레이로 UI 패널(메신저, 대시보드) 유지

### Phase D — 인터랙션 강화

- [ ] 에이전트 클릭 → 프로필 카드 모달 (role/goal/backstory/tools + 현 세션 발화 이력)
- [ ] 도구 호출 시 해당 오브젝트 하이라이트 (검색 단말, 노션 문서함, 파일 캐비닛)
- [ ] 산출물 생성 시 선반에 문서 아이콘 추가 + 클릭 시 미리보기
- [ ] 오류/대기 시 붉은 비네트 효과 (agents-in-the-office 패턴)

### Phase E — 비주얼 톤 조정

- [ ] DeskRPG 스타일 참고: 따뜻한 베이지/크림 색상 **옵션** 추가 (현재 다크 테마 유지 + 라이트 테마 토글)
- [ ] 에이전트별 아바타 이미지 (간단한 SVG 일러스트 or 이니셜 원형)
- [ ] 방 레이블 표시 (MEETING, LOUNGE 등 DeskRPG식 표지판)
- [ ] 가구/식물 등 환경 요소 (CSS 도형 또는 SVG — 최소한으로)

## 3. 우리 컨텍스트 적용 — DeskRPG 스탯 매핑

DeskRPG의 스탯(스트레스/행복도/생산성/연애운)은 소셜 시뮬레이션용.
우리는 **실제 에이전트 실행 데이터**에서 의미 있는 지표를 뽑는다:

| DeskRPG 스탯 | 우리 대응 | 데이터 소스 |
|-------------|----------|------------|
| 생산성 | **태스크 완료율** | TaskCompleted / TaskStarted |
| 스트레스 | **오류 비율** | (AgentError + ToolError) / 전체 이벤트 |
| 행복도 | **토큰 효율** | output_len / tokens_used (적은 토큰으로 많은 출력) |
| 연애운 | *(해당 없음 — 생략)* | — |
| — | **응답 시간** | AgentCompleted.ts - AgentStarted.ts |
| — | **도구 활용도** | ToolUsage 횟수 |

성격 태그도 backstory에서 자동 추출:
- 전략 관리자 → `전략 컨설턴트`, `근거 기반`
- 외부인사 → `Devil's Advocate`, `냉정한 자문`
- 서기관리 → `문서 감사`, `정합성 검증`

## 4. 구현 순서 권고

```
Phase A (메신저) ─── 프론트만 ─── 1일 ─── 체감 변화 최대
    ↓
Phase B (대시보드) ── 프론트만 ─── 1일 ─── 정보 밀도 추가
    ↓
Phase C-1 (CSS 평면도) ── 프론트 ── 2일 ─── 공간감 확보
    ↓
Phase D (인터랙션) ── 프론트+API ── 1일 ─── 클릭 반응
    ↓
Phase E (비주얼 톤) ── 프론트 ── 1일 ─── 마감
    ↓
Phase C-2 (Canvas) ── 선택적 ─── 별도 ─── 게임형 연출 원하면
```

Phase A부터 순차 적용하되, 각 Phase 완료 시 바로 사용 가능한 상태를 유지한다.

## 5. 안 하는 것 (YAGNI)

- 멀티플레이어 기능 (DeskRPG의 공유 오피스) — 로컬 도구에 불필요
- 연애운/소셜 시뮬레이션 스탯 — 실행 데이터와 무관
- LPC 스프라이트 커스터마이즈 — 에셋 라이선스 복잡, SVG/이니셜로 충분
- 오피스 예산 시스템 — 우리는 무료 로컬 모델, 비용 추적 불필요
- RPG Maker 타일셋 — 의존성 과다, CSS/SVG로 대체
